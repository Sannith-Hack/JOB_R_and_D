### System 2: AegisPredict — Proactive Cybercrime & Money Mule Intervention Framework (Smart India Hackathon SIH26184)
- **Role:** AI & Distributed Systems Architect / Lead Technical Contributor
- **Project Type:** Cybersecurity / Graph AI / Spatial-Temporal Machine Learning / Hackathon Solution
- **Current Status:** **Submitted Hackathon Architecture & Verified Python DBSCAN Simulation**
- **Problem Statement ID:** `SIH26184` — *"Development of a Predictive Analytics Framework for Cybercrime Complaints to Forecast Likely Cash Withdrawal Locations in Advance, Enabling Generation of Actionable Intelligence for Timely and Proactive Cybercrime Intervention."*
- **Problem Statement:** Modern financial cybercrimes (phishing, digital arrest, and task scams) rapidly disperse stolen victim funds across multi-layered networks of automated "mule accounts" within minutes. By the time victims file complaints on the National Cyber Crime Reporting Portal (NCCRP) and police register FIRs, illicit funds are physically withdrawn at ATMs or bank branches, rendering traditional post-facto forensic investigations ineffective.
- **Solution & Architecture Blueprint:**
  - **Real-Time Data Ingestion:** Event-driven pipeline ingesting real-time complaint parameters (victim location, transaction timestamps, initial beneficiary bank accounts, IFSC codes, and transaction velocities) via Apache Kafka into a FastAPI backend.
  - **Graph AI Link Analysis (Neo4j + GNNs):** Models bank accounts as Nodes and transactions as Edges. Utilizes custom Cypher path traversal queries (`MATCH (c:Complaint)-[:FUNDS_TRANSFERRED_TO]->(mule1:Account) MATCH path = (mule1)-[:LAYERED_TO*1..5]->(finalMule:Account) WHERE NOT (finalMule)-[:LAYERED_TO]->() RETURN finalMule.account_number, finalMule.branch_location`) to cut through 1–5 layering hops and isolate terminal cash-out mule nodes.
  - **Spatial-Temporal Prediction Engine:** Hybrid predictive model combining an **XGBoost Regressor** (evaluating transaction velocity and withdrawal timing) with an **LSTM network** (capturing sequential historical cash-out patterns) to generate a probability matrix of target extraction bank branches.
  - **Geospatial Hotspot Clustering (DBSCAN):** Implements Density-Based Spatial Clustering of Applications with Noise (DBSCAN) using the **Haversine metric** (`epsilon = 0.1km / 6371.0088`, `min_samples = 3`). Automatically groups tightly packed ATM clusters along commercial corridors or transit hubs into unified operational "Hotspot Polygons" while filtering out isolated ATMs as noise, preventing false-alarm patrol dispatches.
  - **Actionable Intelligence & Alerting Layer:** When a cluster's cash-out probability exceeds 85% within a 2-hour window, the FastAPI backend dispatches real-time WebSocket events. Renders dynamic heatmaps on an LEA Mapbox GL JS dashboard and pushes localized routing alerts to field patrol officers via secure Telegram bots and SMS gateways within a proactive 90-minute intervention window.
  - **Implementation Challenges Solved:** In-memory SHA-256 PII hashing to safeguard banking privacy, PostGIS proximity fallback rules for cold-start areas lacking historical data, and 90-day TTL indexing in Neo4j to maintain RAM efficiency during high-volume complaint streams.
